# CropCard — agent guidance

This file is read by Claude Code (and similar agents) on every session in this repo. Keep it short and actionable.

## What this project is

CropCard is an offline-first PWA replacing the paper "Field Card" for a small-plot Loudoun County, VA farm. SvelteKit + TypeScript, single container, deployed to Azure Container Apps with SQLite + Litestream.

## Invariants — DO NOT BREAK

1. **Safety rules live in `apps/web/src/lib/safety/`.** Plugin JSON files cannot override them. Adding a new rule means editing TypeScript, bumping `RULES_VERSION` in `apps/web/src/lib/safety/version.ts`, and writing exhaustive vitest + fast-check tests.
2. **Plugins are data-only.** No executable JavaScript in any file under `plugins/`. Schema validation at registration is mandatory.
3. **Single replica only.** `infra/azure/main.bicep` sets `maxReplicas: 1` and `revisionMode: 'single'`. SQLite + Litestream is single-writer; multi-replica would corrupt the DB. Do not change these without a database migration plan.
4. **Spray records are immutable after the lock window** (default 48h, FR-09). Server endpoint must enforce this regardless of UI.
5. **Helper role cannot edit locked records or override custom rates.** Server enforces in addition to UI.
6. **Tenant isolation is row-level via `owner_id`** (Phase 18a). Every tenant-scoped repo MUST funnel reads/writes through `tenantWhere`, `withTenant`, or `tenantValues` from `apps/web/src/lib/db/tenant.ts`. The `TenantScoped` brand on schema tables is the compile-time gate; the cross-tenant property test (`apps/web/src/lib/db/tenant.crossTenant.test.ts`) is the runtime gate. Adding a new tenant-scoped table requires: (a) brand it via `tenantScoped(...)` in `schema.ts`, (b) add an `owner_id` column + composite index, (c) wire it into the cross-tenant test, (d) refactor consuming repos. Intentionally-global queries must call `unscopedQueryNote('reason')` in the same function.
7. **AI assists, never gates** (Phase 25 v2 design addendum). Every pre-populated value carries a `provenance` tag (`plugin | data | ai | manual | fallback`) rendered with the `Provenance` component. No-key is a first-class product mode, not an error state — the deterministic fallback path must work end-to-end without an Anthropic key. The `aiTry()` helper at `apps/web/src/lib/server/aiTry.ts` is the *only* place AI degradation conditions (`no-key | over-cap | offline | rate-limit | timeout`) are checked; every endpoint that *could* call Claude goes through it. Lot # is never `ai` — always `manual`. Design source-of-truth: [`docs/design/almanac/AI_PROVENANCE_ADDENDUM.md`](docs/design/almanac/AI_PROVENANCE_ADDENDUM.md).
8. **One inventory chrome** (Phase 27, design ratified 2026-05-26). Every inventory-bearing surface — pesticide, fertility, seed, crop plugin, sprayer — funnels through the same `List → Detail → Edit/Add → List` pattern with a 5-chip type swap on the list. Per-type *fields* differ; per-type *chrome* does not. Crop archetype is a first-class explicit enum on the plugin (`archetype: small-grain.zadoks | row-grain.pollination | dry-seed-legume | winter-squash-cure | continuous-harvest-fruit | cut-and-come-again-leafy | cover-crop.termination | forage-cutting-cycle | perennial-vine-quality | tree-fruit-multi-pick`), NOT inferred from a 5-field combo at render time. The 5-method add flow (barcode · label OCR · AI photo · search · manual) is preserved but routes through the type-aware canonical form, so every entry method writes the same audit/hash-chain row. Stock = lots on hand (instances); Catalog = plugin definitions; the unified surface toggles between them via a segmented control. Design source-of-truth: [`docs/design/almanac/INVENTORY_UNIFICATION.md`](docs/design/almanac/INVENTORY_UNIFICATION.md) + [`direction-almanac-inventory.jsx`](docs/design/almanac/direction-almanac-inventory.jsx) (15 artboards). Open [`docs/design/almanac/inventory-unification-preview.html`](docs/design/almanac/inventory-unification-preview.html) in a browser to walk the prototypes.

## Known follow-ups (not blocking)

These are pre-launch / future-work notes — none block any persona's daily journey.

- **Email transport** — `lib/server/email.ts` logs invite mail to stdout. Wire Postmark/SES/Resend before public launch (call-site shape is stable; swap is localized).
- **Workbox per-tenant cache keys** — Owner switch deletes the cache today; richer namespacing (custom `cacheKeyWillBeUsed` plugin) would avoid the wipe. Workbox precache only takes effect on `pnpm build`; dev mode disables the SW intentionally.
- **Migration runner** — `db:migrate` uses `node scripts/migrate.mjs` (disables FKs around `migrate()` because SQLite ignores `PRAGMA foreign_keys=OFF` inside a transaction and drizzle wraps each migration file in one). Use the wrapper, not bare `drizzle-kit migrate`.
- **ESLint 9 migration** — `--rulesdir ./eslint` is deprecated in ESLint 9. Promote `apps/web/eslint/` to a real plugin package (`plugins: ['cropcard']`) when bumping eslint to v9. Today the lint script wires it via `--rulesdir` and the rule fires.
- **Auth.js magic-link upgrade** — `@auth/sveltekit` is installed; current sessions are HMAC-cookie for v1. Swap is localized to `loginByEmail` + `hooks.server.ts`.
- **Sync-queue conflict resolution** is last-write-wins on the *server*; multi-device same-spray race detection is not implemented (single-farm scope).
- **Push notifications (NFR-06)** not wired.
- **Orchard-specific seasonal calendar** (dormant spray, bloom fungicide) — orchards work as a kernel crop family today, but a richer calendar dataset is future plugin work.
- **AllocationWizard per-step file split** ([#96](https://github.com/mrpeanut01/crop-card/issues/96) follow-on) — the wizard chrome (header + footer) shipped in Phase 25b, but the 2628-line file remains a monolith with shared closure state across the 7 steps. Mechanical split has high regression surface, low UX value; revisit when a contributor needs to edit one step in isolation.
- **Class-specific decon protocols** — `lib/safety/crossContamination.ts` uses generic "previous class differs → decon required" semantics. Three chemistries have stricter SOPs that the kernel doesn't yet model: **Paraquat** (1% bleach + 1% TSP + 3 water rinses), **Glufosinate / Liberty** (detergent + water rinse), **Copper fungicides** (vinegar rinse to prevent next-pass crop damage). Today the user follows product-label decon SOPs; baking these into the wizard is future work.
- **International / Canadian product equivalents** — plugin library is US-label-anchored. EU/CA growers using the same active ingredients see different brand names (Liberty 200 SL vs 280 SL formulation; Roundup Transorb HC in Canada). Not a blocker for the Loudoun-VA primary persona.

## Code style

- Default to no comments; only add when the *why* is non-obvious.
- TypeScript strict mode is on; do not weaken it.
- Field UI must be one-handed-glove operable (≥48dp tap targets, high-contrast).
- Test the safety kernel like a security boundary, not feature code.

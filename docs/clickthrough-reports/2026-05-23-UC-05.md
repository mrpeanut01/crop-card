## Findings

### CT-001 — Tallest-weed input has no accessible name [P2]

- **UC:** UC-05
- **Route:** `apps/web/src/routes/scout/+page.svelte`
- **Expected (per UC-05 step 3 + HCD §2.6):** The "Tallest weed observed (inches)" number input must be programmatically labelled so that screen readers and switch-access users can identify it without relying on adjacent visual context.
- **Observed:** The `<input type="number">` for tallest-weed height has `id=""`, `aria-label=null`, `aria-labelledby=null`, and `aria-describedby=null`. The closest heading ("Tallest weed observed (inches)") has `id=""` and is not associated via any ARIA attribute. The a11y tree exposes the field as bare `spinbutton` with no accessible name.
- **Console:** No errors.
- **Network:** No 4xx/5xx.
- **Screenshot:** `./screenshots/2026-05-23-UC-05-CT-001.png` (scout page at rest with unlabelled input).
- **Recommendation:** Give the input an `id` (e.g. `id="tallest-weed"`) and the heading a matching `<label for="tallest-weed">` (or use `aria-labelledby` pointing at the heading's id). Alternatively add `aria-label="Tallest weed observed (inches)"` directly on the input.
- **Cross-ref:** Extends finding F-F from usability-audit.md (placeholder misuse); the placeholder is now gone but the label association gap remains.

### CT-002 — Decision card (SKIP / SPRAY) has no aria-live region [P2]

- **UC:** UC-05
- **Route:** `apps/web/src/routes/scout/+page.svelte`
- **Expected (per UC-05 step 4 + HCD §2.6 "live regions"):** When the user enters weed counts, the decision heading flips between "SKIP" and "SPRAY" and the supporting rationale text changes. A screen-reader user should hear the outcome announced without manually tabbing to the result section.
- **Observed:** The `<section>` containing the SKIP/SPRAY heading has `aria-live=null` and `role=null`. The only `[aria-live]` element on the page is the empty SvelteKit page-announcer div (assertive, empty). Entering values that cross the threshold produces no live-region announcement.
- **Console:** No errors.
- **Network:** No 4xx/5xx.
- **Screenshot:** `./screenshots/2026-05-23-UC-05-CT-002.png` (SPRAY decision state — decision card in viewport).
- **Recommendation:** Wrap the decision `<section>` (or at minimum its heading + rationale paragraph) in `aria-live="polite"` so the SKIP ↔ SPRAY transition is announced. `aria-atomic="true"` is appropriate so the full decision text is read, not just the changed fragment.
- **Cross-ref:** Mirrors finding F-G from usability-audit.md (missing aria-live on spray safety result); the scout page has the same gap on a different route.

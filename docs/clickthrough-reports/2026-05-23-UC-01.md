## Findings

### CT-001 — Companion Advisor dialog has no close button; "No thanks" buttons may be outside viewport [P2]
- **UC:** UC-01, step 4
- **Route:** `/plan?tab=crops`
- **Expected (per use-cases.md UC-01 step 4):** Companion-system advisor proposes a layout — accept to batch-add. Implicit: user can dismiss the advisor without accepting.
- **Observed:** The "🌽 Companion Advisor" dialog (role=dialog) presented 6 companion suggestions each with its own "No thanks" button. No dialog-level close/dismiss button (X or Cancel) was present. The "No thanks" buttons rendered below the viewport fold for suggestions beyond the first visible one. The Escape key did not close the dialog. Keyboard-only users cannot dismiss the dialog without scrolling to each "No thanks" button in sequence.
- **Console:** No errors related to this.
- **Network:** No 4xx/5xx.
- **Screenshot:** ./screenshots/2026-05-23-UC-01-CT001-companion-dialog.png
- **Recommendation:** Add a single "Dismiss all / No thanks to all" button in the dialog header, and/or a standard close (X) button that dismisses the entire advisor. Ensure Escape key closes the dialog (add `on:keydown` handler or use native `<dialog>` element behavior).
- **Cross-ref:** Likely relates to UC-07 companion advisor design.

### CT-002 — Planting date stored one day earlier than entered (timezone offset) [P2]
- **UC:** UC-01, step 3
- **Route:** `/plan?tab=crops` (form submission)
- **Expected (per use-cases.md UC-01 step 3):** Pick a date → Add planting. Date entered: 2026-05-25.
- **Observed:** The stored/displayed planting date is 2026-05-24 across `/harvest` ("Planted 5/24/2026") and `/today` ("Plant Tomato — Roma VF" shown on 5/24). The HTML date input value "2026-05-25" is interpreted as UTC midnight 2026-05-25T00:00:00Z, which corresponds to 2026-05-24T20:00:00 US/Eastern. The server apparently stores/displays in UTC (or strips the time component at UTC boundaries), causing a one-day display shift for users in US time zones entering near-midnight-UTC dates.
- **Console:** No errors.
- **Network:** No 4xx/5xx.
- **Screenshot:** N/A
- **Recommendation:** Parse the date input value as a local calendar date (YYYY-MM-DD string) rather than a UTC instant. Store as a `DATE` column type (or a `TEXT` date string without time component) to avoid timezone conversion. Alternatively, display dates in the user's local timezone throughout.
